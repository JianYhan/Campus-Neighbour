## 2 本地环境与配置方案

前端按pnpm管理，后端按Maven Wrapper管理；运行时版本在[架构](architecture.md)验证后固定。Docker Compose用于数据库、Redis及初期部署，前端开发服务代理/api和/ws至后端。Nginx生产统一入口提供HTTPS、静态文件与API/WebSocket转发。

| 配置类别 | 计划配置 | 内容及保管 |
| --- | --- | --- |
| 数据库 | DB_HOST/DB_PORT/DB_NAME/DB_USER/DB_PASSWORD | 本地与部署分离；应用账号最小权限，迁移权限单独考虑 |
| Redis | REDIS_HOST/REDIS_PORT/REDIS_PASSWORD | 会话存储；限制网络访问，不公开端口 |
| 文件 | UPLOAD_ROOT、MAX_UPLOAD_BYTES | 持久化目录与服务端限制；可用空间监控 |
| 入口 | PUBLIC_ORIGIN、允许来源 | 同源HTTPS，不能通配放开携带凭据的来源 |
| 会话 | SESSION_TIMEOUT、Cookie安全配置 | 过期时间待D01，生产Secure/HttpOnly及CSRF |
| 日志 | LOG_LEVEL、日志保留配置 | 不输出密码、token和完整聊天 |
| 演示 | DEMO_DATA_ENABLED | 仅演示环境，生产禁用自动演示数据 |

上表名称是建议配置接口，实际Spring属性映射在实施时说明；不保证框架自动识别这些名称。只提交无秘密值的环境模板，实际秘密由环境注入。

## 4 部署与发布

初期单实例：Nginx、应用、PostgreSQL、Redis与持久化图片卷。数据库和Redis仅内部网络访问；证书自动续期方式待域名和平台确定。配置健康检查及重启策略，转发WebSocket升级和适当超时。

发布流程：指定Git提交→运行规定测试与构建→保存版本产物→备份数据库及图片→检查迁移影响→部署→检查健康与两个用户核心流程→记录发布结果。数据库迁移不保证可逆，回滚必须考虑旧应用与新结构兼容；不得仅回退镜像就声称回滚成功。

本项目采用TDD，功能在开发期间持续测试；发布检查补充真实环境验证，不替代测试先行。发布权限与审批责任待团队填写。

## 5 数据持久化、备份与恢复

数据库和图片必须在持久化卷，不能在容器临时层。建议每天及每次迁移前备份数据库与图片清单／文件，保留周期、恢复时间和允许数据损失目标待D11/D12确认。备份不放公开仓库。

恢复演练：在隔离环境恢复数据库→恢复匹配的图片→检查记录数量、图片引用与文件存在性→登录两个虚构用户查看历史交易／聊天→确认没有开放测试环境外部写入→记录恢复耗时、缺失与处理。Redis会话丢失可以重新登录，业务历史不得丢失。

## 6 运行检查与常见故障

| 现象 | 检查与处理 | 不应做的事 |
| --- | --- | --- |
| 登录失败或立即掉线 | 查Cookie域／Secure、代理、CSRF、Redis和时钟；查看脱敏requestId日志 | 直接关闭鉴权或CSRF |
| 消息不实时 | 查/ws代理、CONNECT鉴权、用户订阅、outbox；重新取历史 | 把未保存消息标为成功 |
| 预约返回409 | 刷新真实商品与交易状态，检查是否已占用／版本变更 | 覆盖状态绕过唯一约束 |
| 图片丢失 | 查持久化卷、存储键与备份，恢复缺失文件 | 修改数据库路径掩盖丢失 |
| 迁移失败 | 保留日志、查数据库版本及已执行迁移，修正后按批准流程继续 | 删除历史迁移记录强行重跑 |
| 测试不稳定 | 查共享数据、时间控制、并发等待和异步清理 | 随意增加sleep或跳过测试 |

健康检查、请求错误率、数据库连接、磁盘空间、待推送事件数量为基本观察项；阈值经测试后确定。实际告警渠道待填写。

## 7 学生用户操作说明

以下是预期操作，按钮最终名称随中英文设计调整；功能尚未上线。

### 注册与资料

进入登录注册页，填写邮箱、昵称和密码。注册成功后登录；校园认证方式尚未确定，不能把普通注册称为学校认证。在“我的资料”选择是否填写学院、专业、年级、课程教师及简述；先预览公开信息。

### 发布与找商品

点击“发布”，填标题、描述、价格、分类、成色、楼栋并上传图片。教材补课程、作者与版本；愿意换物时开启选项并写想换什么。预览后发布。在列表按关键词、课程、楼栋、价格组合筛选，打开详情核对版本和商品状态。

### 与对方聊天

详情点击“联系卖家”。选择问价格／问物品状态／问交易地点，确认发送预填问题；也可选择自由聊天，每条暂限20个可见字符，可连续发多条。消息发给真实交易对方，不由AI回复。失败时点击重试；“已发送”表示平台已保存，不代表对方已读。

### 预约、面交和评价

双方聊天约定地点时间后，由卖家在会话建立预约。买家在“我的交易”查看安排；交付确认前可取消并说明原因。线下面交后，买家核实收到物品再点击“确认收货”；完成后双方可评价。该确认只代表交易交付状态，不表示平台代收款。

### 支付入口

点击Pay显示“暂时无法提供支付方式”，可直接返回。系统不接入付款、不产生支付成功记录，进入该页不会阻塞线下面交与收货确认。

### 换物

选择对方允许换物的商品，挑选自己的一件可交易商品，填写面交安排后发出请求；请求待接受时不占用物品。对方接受后锁定两件商品，线下交换后双方分别确认。只确认一方时显示“等待另一方确认”；有分歧保留记录，不能当作已经完成。

### 主题、语言与通知

导航切换中文／英文和深色／浅色。用户商品文字及聊天不自动翻译，已输入消息不应丢失。通知入口查看新消息、预约、取消和完成；点击后进入有权限的详情。

## 8 管理员说明

受控分配管理员账号后进入管理页。处理违规商品或限制账号时选择对象、填写原因并确认，操作留审计；恢复可见性与恢复账号是独立动作。可以维护校园字典及专区时间条件，不能冒充用户确认收货、删除交易历史或阅读私人聊天。
